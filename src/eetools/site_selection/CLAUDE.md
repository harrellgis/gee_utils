# site_selection/ — conventions

`site_selection/` is a **workflow** subpackage: it proposes TGBS reference and degraded sites for a focal site (spec: vault `raw/notes/gee_utils/2026-11-05-gee-utils-site-selection-simplified-spec-design.md`, amended §0a by `2026-11-07-gee-utils-degraded-anchor-design-review.md`). Design rule: **reduce once, score in Python.** Earth Engine is touched only by `predictors.py` (and the focal geometry read in `domain.load_focal_geometry`); everything in `domain`, `similarity` and `scoring` is pure pandas/numpy and unit-tested without credentials.

- **Grids are client-side.** Cells are `(size, ix, iy)` in the focal UTM zone with corners at `ix*size`; `cell_id = "<size>_<ix>_<iy>"`. Fine cells nest exactly in coarse cells and the 250 m fraction-image grid nests in both, because `k ∈ ALLOWED_K = (1, 2, 4, 8)`. Only integer indices travel to EE (`cells_feature_collection`).
- **`ScreeningTables` hold raw reductions only**, one `_done_<family>` flag per reduction family, keyed by `cell_id` (embeddings by `(cell_id, year)`). Never store pools, MESS, percentiles or ranks there. Anything that changes a raw value must be in the provenance key built in `workflows._run`; tolerances and weights must not be.
- **Determinism:** pools are sorted by `cell_id` and ties broken by `cell_id` (`scoring.sort_by_score`) so a run on reused tables is bit-identical to a fresh run. Keep it that way.
- **Joins:** use `workflows._join_new` (adds only missing columns). Build pools from fresh `store.table(level)` values first: earlier snapshots go stale after `ensure(...)` adds families.
- Each layer family is reduced at its native scale (90 m gates, ~4.6 km climate, 100 m terrain/soil, 250 m NDVI/fractions, 500 m NBAR, 30 m canopy); never oversample to `analysis_scale_m`. Focal-plus-buffer pixels are masked with `RunContext.outside_mask()` before every candidate reduction (not climate).
- Thresholds, ladders, class/soil group tables and profiles live in `constants.py` (`SEARCH_LADDERS`, `VECEA_CLASS_GROUPS`, `WRB_RELATED_GROUPS`, `MESS_RANGE_FLOORS`, `SOP_MATRIX_THRESHOLDS`, `DEGRADATION_TYPE_PROFILES`).
- Hansen `lossyear` is masked where no loss occurred: always `unmask(0)` before comparing years (as `sensors.hansen.get_forest_loss_in_period` now does).
- **Degraded sites are the 0% rescale anchor** (§0a). The order is constrain → gate → rank in `workflows._rank_degraded`:
  - `scoring.anchor_constraint` (D1): NDVI + NDMI, `D_base <= F_base` and `D_now <= min(F_base, F_now)`;
  - `scoring.pathway_gate` (D2) on `pct(signature_sim)`;
  - `degradation_score` on state + trajectory.

  Never put `signature_sim` back into a ranking weight: it penalises sites further along the same pathway.
- **Absolute eligibility, relative ordering (v0.6.0).** The `dw_landuse` family (one 30 m reduction of yearly Dynamic World modes, `DW_LANDUSE_FIRST_YEAR`..`end_year`, on every final cell) feeds `scoring.landuse_history`: the reference gate (`persistent_natural`), the conversion pathway test for degraded runs (`scoring.conversion_pathway`, conversion types only; it replaces D2 there), the DW built-up filter and the corrected `natural_frac`. Store year shares, never a thresholded band, so tolerances stay out of the provenance key. Percentiles only order eligible cells; never derive an eligibility or matrix threshold from the pool.
- **Reference intactness (0.8.0)** never ranks on greenness: `ReferenceWeights.performance` / `moisture` default to 0 (circular 100% anchor; plantations are greener), gHM `naturalness` is 0.10, `natural_persist` 0.25 and `low_loss` (pct(1 - `loss_since_2000_frac`)) 0.15; the forest shifts default to 0. The gate defaults to natural in **every** DW year at >= 0.9. These reproduce the 2026-11-11 tuned scores exactly (vault `2026-11-11-gee-utils-site-selection-reference-tuning-basemap-review.md`). Greenness stays in D1 and the degradation score.
- **Gate, then thin** (`scoring.gate_then_thin`): every filter removes cells before thinning and before the stop rule. Each removed cell keeps a `gate_reason`, and `result.pool` holds eligible and gated-out cells (`pool_status`). `project_start_year` is a completable key field (`types.COMPLETABLE_KEY_FIELDS`); the baseline bands are separate families (`ndvi_base`, `nbar_base`) so reference tables are completed rather than invalidated.
- **Top candidates (0.6.1)** are pure pandas after the ladder (`scoring.select_top_candidates` in `_assemble`): they never change the shortlist, eligibility or scores. Keep the score column names clear of `scoring._TIEBREAK_COL`. From 0.6.2 the workflows take `top_candidates_n` / `top_candidates_condition_weight`; the pool carries `mandatory_met` + automated `<criterion>_score` for every eligible cell (`scoring.sop_pool_columns`; spaced cells keep the shortlist-matrix values), and `result.top_candidates` leads with `TOP_CANDIDATE_FLAGS` + `mandatory_met` (from 0.9.0 it is not exported as its own file: its `top_rank` / `top_score` / `proposed` columns are folded into the exported pool). Flags and SOP status are shown, never used to filter or rank.
- **Exports (0.9.0) are slim** (vault `2026-11-14-gee-utils-site-selection-output-audit.md`): `export_site_selection` writes `<kind>_pool.gpkg` (`workflows.pool_export_frame`), the slim `<kind>_ranked.csv` (`shortlist_table`), the selection matrix and the layer register, all CSVs with `index=False`; `export_proposed_sites` writes the stamped proposed-sites file with `cell_id`. Never export raw `*_mean/_p10/_p50/_p90` statistics (they are in `ScreeningTables`), the always-true Stage 1 `gate_*` flags, `pred_*` copies or per-run constants: per-run values go in the layer register. Slim only at export; `result.pool` / `result.ranked` keep every column in memory.
